\section*{Scope}
This manual describes the 2.x source tree, Autotools build, and scanner API.
The repository's \texttt{README.md} and \texttt{doc/scanner\_api.md} are the
authoritative references and are updated with the source.

\section*{Build and test}
For a Git checkout, install the dependencies listed in the README, then run:
\begin{Verbatim}
bash bootstrap.sh
./configure
make
make check
\end{Verbatim}
Release archives already contain \texttt{configure}, so they do not require
\texttt{bootstrap.sh}. Use \texttt{make distcheck} before a release or when
changing the build/distribution manifests. The source tree includes the be20
API and DFXML dependencies; do not initialize recursive submodules.

\section*{Source layout}
\begin{itemize}
\item \texttt{src/} contains the executable, built-in scanners, and the
  integrated \texttt{be20\_api} component.
\item \texttt{doc/scanner\_api.md} defines the scanner contract and
  \texttt{doc/scanner\_template.cpp} is the loadable-scanner starting point.
\item \texttt{tests/} and the project Makefiles contain regression and
  integration tests. Run them through \texttt{make check}.
\item \texttt{.github/workflows/} contains the supported CI builds, including
  the MinGW Windows artifact build.
\end{itemize}

\section*{Scanner lifecycle}
A scanner is a \texttt{scanner\_t} function that switches on
\texttt{scanner\_params::phase}. In \texttt{PHASE\_INIT}, call
\texttt{sp.check\_version()}, name the scanner, and declare feature recorders,
histograms, flags, and scanner options. In \texttt{PHASE\_INIT2}, retrieve
declared recorders. \texttt{PHASE\_SCAN} may run concurrently on multiple
worker threads, including concurrent calls to the same scanner. Treat
\texttt{sp.sbuf} as read-only and valid only during that callback. Finish
scanner-owned output in \texttt{PHASE\_SHUTDOWN} and release state in
\texttt{PHASE\_CLEANUP}; cleanup also runs for disabled scanners.

Declare feature recorders only in \texttt{PHASE\_INIT}; retrieve them in
\texttt{PHASE\_INIT2}; write findings during \texttt{PHASE\_SCAN}. Recorder
writes are safe concurrently, but other shared scanner state needs appropriate
locking or atomics. A scanner can be bypassed for ineligible buffers, so it
must not assume it sees every input buffer.

\section*{Loadable scanners}
Copy \texttt{doc/scanner\_template.cpp}, rename its scanner and metadata, and
build it against the same bulk\_extractor source version as the executable. A
module named \texttt{scan\_*} exports:
\begin{Verbatim}
extern "C" scanner_t *bulk_extractor_scanner_v1();
\end{Verbatim}
Use \texttt{-P} to load a development module from an explicit directory. The
loader also searches \texttt{BE\_PATH}. Keep all factory and lifecycle rules
from \texttt{doc/scanner\_api.md}; do not retain \texttt{scanner\_params} or
pointers into an \texttt{sbuf} after a callback returns.

\section*{Windows executable}
The project does not support a native Windows build or an installer. The
\texttt{Windows MinGW build} workflow cross-compiles a 64-bit executable on
Ubuntu using the x86\_64 MinGW-w64 POSIX toolchain. It builds static Expat,
RE2, and Abseil through a pinned vcpkg checkout, configures with
\texttt{--host=x86\_64-w64-mingw32 --disable-libewf}, and links the executable
with \texttt{-all-static}. The workflow uploads a Windows artifact containing
\texttt{bulk\_extractor64.exe}.

The CI job rejects unexpected non-system DLL imports. A Windows runner then
downloads and executes that same artifact against an input directory with a
Unicode filename. The artifact does not include libewf, so it cannot read E01
images. Treat it as a CI artifact, not a signed release package.
