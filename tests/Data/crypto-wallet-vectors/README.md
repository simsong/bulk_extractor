# Crypto wallet test vectors

These fixtures specify the proposed wallet-discovery output contract in
doc/Crypto.md. They are deliberately generated test material; no fixture has
funds or production use.

The JSON files use the synthetic format `be-wallet-test-v1`. It is **not** a
real wallet-product format and must not be accepted by a production wallet
adapter. It exists to test output classification before product-specific
adapters and vectors are added.

| Fixture | Expected classification |
| --- | --- |
| plaintext-single-wallet.json | parsed wallet, not_encrypted, single, private_key |
| encrypted-multicurrency-wallet.json | parsed test envelope, encrypted, multi, encrypted_vault |
| encrypted-single-wallet.pem | parsed PKCS#8 container, encrypted, single/unknown currency, encrypted_private_key |
| unknown-ciphertext.txt | not a wallet; no wallet record in conservative mode |

The JSON ciphertext was generated by encrypting the documented plaintext
envelope with `openssl enc -aes-256-cbc -pbkdf2 -salt -pass pass:password -a`.
The only password is `password`. The plaintext single-wallet vector carries a
generated, deliberately unprotected test key only to test the explicit
not_encrypted classification. Do not use it outside this corpus.

Future real-wallet fixtures must be generated by the corresponding wallet
software, with test-only accounts and password `password` where encryption is
needed. Each must document product version, creation steps, expected parse
fields, and whether every recognized sensitive field is encrypted.
